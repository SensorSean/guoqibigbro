# 回归测试

V1.3.3 新增。用于锁死两处曾造成**静默写错数据**的缺陷，防止后续改动回潮。

## 运行

```bash
pip install pytest
python -m pytest tests -q
```

期望结果：**40 passed**。

## 文件说明

| 文件 | 项数 | 锁死的行为 |
|---|---|---|
| `test_rowkey_normalize.py` | 22 | 行标识归一化：并列连词「之 / 及」不得误截断；区段「之X段」与区间「A至B」的收敛能力不得被破坏 |
| `test_synonym_split.py` | 18 | 同义词分组：「项目负责人」与「项目经理」必须互斥，不得被互相匹配 |

## 这两组测试为什么重要

被锁的两个缺陷都**不会报错**。程序正常跑完、进度条走满、表格也填满了，
但填进去的值是错的 —— 一个是 A 行的数据被填进了 B 行，一个是「项目负责人」整列填成了
「项目经理」的人。这类缺陷只能靠断言提前拦住，靠肉眼复核几乎发现不了。

## 关于测试样本中的项目名

样本取自真实生产数据，因此在同步到 GitHub 开源副本时会被自动脱敏
（真实项目名 / 路名替换为「示范路」「示例学校」等虚构名）。

替换由 `00-github副本生成/gen_github_copy.py` 的 `sanitize_tests()` 完成，
**只替换专有名词、保持语言结构不变**（连词、区段标记、期次写法一律不动），
因此断言在脱敏后依然有效。

新增测试用例时请注意：
- 如需引入真实名称，务必同步在 `gen_github_copy.py` 的 `TEST_SANITIZE_MAP` 中补映射，
  否则会**把真实项目名直接推到公开仓库**；
- 不要把「之 / 及 / 至 / 到 / 段 / 区间 / 幅」这些词本身写进映射表，它们是被测对象。
