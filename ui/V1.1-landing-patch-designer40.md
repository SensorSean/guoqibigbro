## 1. 顶部导航响应式方案（回答 Q1）

### 1.1 空间分配（删除 `.app-author` 后）
删除作者标签后，**不需要手动"分配"空间**——交给 flex 即可：
- **品牌区（`.logo`）**：`flex:0 0 auto` + `white-space:nowrap` → 永不收缩、永不换行，始终占据其自然宽度（图 32px + 标题 18px + 副标题）。
- **导航区（`.nav-tabs`）**：`flex:0 1 auto` + `margin-left:auto` → 顶栏级右对齐，吃掉 logo 右侧全部剩余空间；空间不足时**内部横向滚动**而非挤压。
- 两者都不会重叠：品牌有 `min-width:0`（防子项溢出撑破），导航有 `overflow-x:auto`（防溢出串位）。

### 1.2 小窗口策略（900px↓ / 768px↓）
**不分发文字隐藏/换行，统一走横向滚动**；仅做"美观压缩"：
- `≤960px`：隐藏英文 `.subtitle`（回收 ~120px），tab 内边距 16→12px。
- `≤820px`：顶栏 padding 24→16、gap 16→12，tab 字号 13→12px、内边距收紧。
- `≤680px`：logo 字号 18→16、logo-img 32→28px，tab 内边距再收紧。
- `≤520px`：维持横向滚动，不加汉堡菜单（桌面工具 5 短标签始终可见更优）。

### 1.3 logo 区是否需要 flex-shrink / min-width
**需要**。明确给：
- `.logo { flex:0 0 auto; min-width:0; white-space:nowrap; }` → `flex-shrink:0` 保证品牌不被压扁/重叠；`min-width:0` 允许 flex 正确计算收缩起点。
- `.nav-tabs { flex:0 1 auto; min-width:0; }` → `flex-shrink:1` 允许导航在窄窗收缩到能触发滚动；`min-width:0` 是触发 `overflow-x` 的前提（默认 `min-width:auto` 会让 flex 项拒绝收缩到内容宽度以下，从而撑破容器）。
- `.nav-tab { flex:0 0 auto; white-space:nowrap; }` → tab 保持自然宽度，靠滚动而非压扁。

## 2. 预览确认 + 执行结果 合并 UI 方案（回答 Q2）

### 2.1 导航结构（6 → 5）
`0 数据源 · 1 字段映射 · 2 预览执行 · 3 使用说明 · 4 关于`
合并页放在**第 3 位（index 2）**，原 `switchPage(2)` / `renderPreview()` 逻辑零改动；原「执行结果」(index 3) 删除，其后页签前移。

### 2.2 信息架构（单页纵向滚动）
```
┌───────────────────────────────────────────────┐
│ [📋 预览执行] 共 N 字段·已匹配 M 个  [✅ 确认执行]│  ← 页头：标题+状态 / 主操作(run-btn)
├───────────────────────────────────────────────┤
│ ▸ 预览表格（可折叠 .preview-panel）              │
│   行号|姓名(来自…)|部门(来自…)|状态  ···前5行     │  ← renderPreview 渲染，max-height 收敛
│   [✏️ 返回修改]              [预览表格 ▾]        │  ← 左：回字段映射；右：折叠开关
├───────────────┴───────────────────────────────┤
│ ——————— 执行 ———————                          │
├───────────────────────────────────────────────┤
│             ◯ 进度环 0%                         │  ← .progress-ring / #progress-circle
│   ┌─────────────────────────────────────┐     │
│   │ ✅ 已加载 数据源 / 匹配率 / 完成日志   │     │  ← #log-list（scrollIntoView 自动聚焦）
│   └─────────────────────────────────────┘     │
│   [📂 打开结果文件](#export-btn) [🔄 新建任务](#reset-btn) │
└───────────────────────────────────────────────┘
```

### 2.3 关键交互（designer-15 §8.3 补强）
- 点「✅ 确认执行」→ `confirmAndExecute()` 去掉 `switchPage(3)`，直接 `await doExecute()`；`.run-btn` 隐藏、`.preview-panel` 加 `.locked`（禁止误触）。
- 进度 100% → `renderLogs()` + 显示 `export-btn`/`reset-btn`；自动 `.preview-panel.collapsed` 收起预览并 `log-list.scrollIntoView({behavior:'smooth'})`。
- 预览表容器 `max-height:360px; overflow:auto` 收敛高度。
- 加「✏️ 返回修改」(`switchPage(1)`) 入口。

### 2.4 必须保留的 id（保证 app.js 不改写）
`page-2` / `preview-table` / `preview-info` / `progress-circle` / `progress-text` / `.progress-ring`(done) / `log-list` / `export-btn` / `reset-btn`。

### 2.5 app.js 最小改动
- `confirmAndExecute()`：删 `switchPage(3);`，仅留 `await doExecute();`。
- `switchPage()`：`if(idx===2) renderPreview();` 不变。
- 键盘导航上限 `if(currentPage<3)` → `if(currentPage<4)`。

## 4. 设计风险与验收要点（回答 Q4）

### 风险
- **R1 合并页过长**：预览表行多 + 进度 + 日志叠加，整页超长 → 已用 `max-height:360px` 收敛预览表、执行完自动折叠预览。
- **R2 双触发**：确认执行后预览仍可点 → 已加 `.locked` 锁定 + 隐藏 `.run-btn`。
- **R3 tab 不可达**：final 预览的 `flex:1 1 auto; justify-content:flex-end` 在溢出时首个 tab 滚到起点不可达 → 本补丁用 `flex:0 1 auto` 修正。
- **R4 视觉噪音**：designer-20 建议在顶栏加 V1.1 药丸，与 team-lead 指令冲突 → 不采纳，保持顶栏简洁。
- **R5 命名不一致**：`v1.1-preview.html`/`v11-preview.html` 用"执行结果" → 全仓库统一为「预览执行」。

### 验收要点（Acceptance）
- [ ] 拖动/缩放窗口至 900px、768px、520px、400px，顶栏**不串位、不重叠**；tab 可横向滚动且**首个 tab 始终可达**。
- [ ] `≤960px` 时副标题消失，logo 与 tab 仍单行对齐。
- [ ] 顶栏无「软件作者：LuoLei」；「关于」页作者信息（LuoLei）仍在。
- [ ] nav 由 6 → 5；第 3 个为「预览执行」；`.page-dot` 由 6 → 5。
- [ ] 字段映射「确认并预览」→ 合并页预览正常；「✅ 确认执行」→ 进度 0→100% → 日志 + 打开结果/新建任务；全程无页面跳转。
- [ ] 合并页全部原 id 保留，`app.js` 仅微调（无重写）；打开结果/新建任务功能正常。
- [ ] 「关于」页 `V1.0→V1.1` + 更新日志模块展开正常；使用说明标题有 V1.1 药丸。
